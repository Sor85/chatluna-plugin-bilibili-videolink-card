# Agent Note: B 站视频卡片迁移至 ChatLuna v2

Status: implemented

## Problem

旧插件基于 Koishi 配置与中间件，含重复队列、无生命周期清理的定时器、未生效的解析上限，以及仅信任响应头的下载限制。视频解析还依赖第三方 HTTP 服务。新插件需要遵守 Cordis 4 生命周期和 ChatLuna v2 WebUI 规范。

## Decision

- 插件独立源码单向同步到 v2 workspace；源码无依赖与锁文件，使用宿主构建、类型检查和测试。
- 使用宿主 `koishi` 兼容服务的 `attach` 事件读取通过用户/群过滤后的入站消息，发送统一走 `ctx.chat.send`，不使用旧插件代码作为运行依赖。没有选择 `chat/before-receive`，因为它在 AI 引擎关闭时不会执行。
- 采用 camelCase 的新配置契约，删除旧配置别名、已废弃的双层队列和前置中间件开关。新契约由 `src/config.ts` 唯一定义。
- 配置页按「基础 → 解析范围 → 消息与卡片 → 视频发送 → 队列 → 网络」分组。解析来源用 `parseLinks` / `parseShares` 两个开关，因为宿主把 `role('checkbox')` 数组渲染为芯片选择器；`idPreference` 仅在 `showLink` 开启时显示。受限提示文案和网络调试默认折叠。三条受限提示不随 `filterAction` 隐藏：联动分支未命中时字段解析为空，会让时长过滤失效。
- 官方 view / playurl 接口替代第三方解析，支持分 P；仅接受完整单段 MP4。保留短链的原始域名，逐跳验证重定向和 CDN，下载逐块限额并响应卸载取消。
- `src/media.ts` 通过原生 `chat.encoder` 为本插件的已下载 OneBot 视频保持内联发送：默认宿主将大于 5 MiB 的媒体转成 file://，远程协议端及沙盒无法读取该路径。只认本插件标记并再次验证大小，不修改全局媒体配置或沙盒实现。
- 缓冲不随每条输入重置；串行队列有上限；每条消息 parseLimit 真正生效；去重按 route、标准化 BV 与分 P。等待提示在 finally 清理。
- 图片渲染保留 Takumi 和字体依赖。外部文本在 HTML 构造时转义，在解析后的节点树中解码，避免 HTML 实体原样显示且不让文本变成标签。资源失败使用中性底色。
- `client/outputs-field.tsx` 使用 ui-kit Field / Checkbox，只注册本插件的数组 role，配置保存与撤销由宿主承担；不创建独立页面或配置接口。

## Alternatives considered

- 直接嵌入旧插件：保留 Koishi v1 风格、重复实现与缺陷，拒绝。
- 原生 Satori 全局 message 监听：会绕过宿主已存在的用户/频道过滤，拒绝。
- 使用浏览器截图生成卡片：增加浏览器进程和清理负担，保留无需浏览器的 Takumi。
- 保留第三方解析服务：增加内容转发、可用性与明文传输依赖，采用已验证可用的官方接口。

## Consequences

- 对话模型关闭时仍可独立解析视频，但宿主的忽略用户/频道设置继续生效。
- 新配置不兼容旧字段；大小上限不再允许无限制下载，视频清晰度和权限受官方公开 API 约束。
- 只有图片时不请求视频源；附加信息失败明确降级；不支持普通视频之外的 B 站内容。
- 单元测试覆盖解析、过滤、队列、下载边界、真实 PNG 和配置守卫；端到端验收使用独立 onebot-sandbox 空间。

# Agent Note: Bilibili video cards on ChatLuna v2

Status: implemented

## Problem

The Koishi plugin had duplicated queues, timers without lifecycle cleanup, an ineffective per-message limit, and downloads limited only by the declared Content-Length. Video resolution depended on a third-party HTTP endpoint. The migration needs Cordis 4 lifecycle ownership and the ChatLuna v2 WebUI contract.

## Decision

- Keep independent source and sync it one-way into the v2 workspace. Dependencies, builds, type checks and tests belong to the host copy.
- Listen to `attach` from the host's Koishi compatibility service, after user/channel checks, and send through `ctx.chat.send`. Do not load the legacy plugin. `chat/before-receive` is unsuitable because it does not run when the AI engine is off.
- Define a fresh camelCase contract in `src/config.ts`. Remove old aliases, the unused second queue and the prepend-middleware option.
- Group the settings page as basics, parse scope, messages and card, video delivery, queue, then network. Parse sources are the `parseLinks` / `parseShares` switches because the host renders `role('checkbox')` arrays as a chip picker. `idPreference` appears only while `showLink` is on. Limit notices and network/debug start collapsed. The three limit notices are not hidden by `filterAction`: a conditional branch that does not match leaves them unset, which would disable duration filtering.
- Use official view/playurl endpoints instead of third-party parsing. Preserve video parts, accept complete single-file MP4 only, validate each redirect/CDN and enforce streamed byte limits with lifetime cancellation.
- `src/media.ts` uses the native `chat.encoder` API to preserve inline delivery for this plugin's downloaded OneBot videos. The host otherwise turns media larger than 5 MiB into file:// paths unavailable to remote adapters and the sandbox. The encoder recognizes only this plugin's marker and rechecks size, without changing global media settings or the sandbox.
- Buffer from the first queued message, cap the queue, enforce per-message parseLimit and deduplicate by route, canonical BV and part. Recall waiting messages in finally.
- Retain Takumi and the font packages. Escape untrusted HTML, then decode entities in the parsed node tree, never raw HTML. Missing images use a neutral placeholder.
- Register only the plugin-specific array role in `client/outputs-field.tsx`, using ui-kit Field/Checkbox. The host retains ownership of save, reset and JSON editing; no separate settings API or page.

## Alternatives considered

- Embedding the old plugin would retain its lifecycle and queue defects.
- Global Satori message listeners would bypass existing user/channel filters.
- Browser screenshots would introduce browser processes and cleanup overhead without improving this static card feature.
- Retaining the third-party service would add availability and plaintext data-sharing dependencies; the official public MP4 endpoint was verified instead.

## Consequences

- Parsing works without a responding model while host user/channel ignore settings remain effective.
- Old configuration keys are not supported. Unlimited downloads are removed. Public API permissions and quality constraints still apply.
- Card-only mode never requests a video stream. Optional details degrade independently. Non-video Bilibili content remains unsupported.
- Tests cover input parsing, filters, queues, download boundaries, actual PNG output and repository contracts. End-to-end acceptance uses an isolated onebot-sandbox space.
